# FEAT-13: Parent account

> Implements: ACC-01..07, NFR-14 (D15, ADR-03, ADR-07) · Screens: SCR-13 (new), SCR-11 ("Account" row)
> Status: designed · Branch: `feat/FEAT-13-account` · 2026-11-16

## Scope

The parent can create an account (email + password, verification email), sign in with email + password or Google, reset a forgotten password from an emailed link, sign out, and delete the account (PIN confirm). All of it lives on SCR-13 inside the PIN-protected parent area; the session is kept in Android's encrypted storage. The server gets email (SMTP) and Google OAuth configured from repo secrets, email templates whose links open two small web pages it serves, and tests that run the email flows against a local mail sink.

Not in scope: syncing anything, "Last sync" and "Sync now" on SCR-13 (FEAT-14, SYN-07); the reset epoch (SYN-06); the app rename (FEAT-16). No Drift schema change.

## Design decisions (this feature)

- **Server config from env on every start, not in a migration.** New `server/pb_hooks/config.pb.js` runs `onBootstrap` (after `e.next()`): sets `meta.appURL` from `SERVER_HOSTNAME`, SMTP from `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `MAIL_SENDER_ADDRESS` (sender name = app name; SMTP on only when host and sender are set), and the `users` Google OAuth2 provider from `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` (OAuth2 on only when both are set). It saves only when something changed. Why: migrations run once, so secrets Ken adds later, or a new hostname (brainbubblz.com), would never reach the server. `install.sh` writes these keys (from stdin, as it does the superuser) into `/etc/default/numberninja-pb` (mode 600), which the unit already reads; `deploy.sh` and `deploy-server.yml` pass the new secrets through. Missing secrets leave the feature off, never fail the deploy.
- **Email provider: Brevo SMTP on port 2525** (recommended; Resend works the same on 2587). DigitalOcean blocks 25/465/587 on droplets; Brevo's free plan (300 emails/day) lets Ken verify a single sender address if domain records aren't wanted. PocketBase only speaks SMTP, so the "email API" of `04-architecture.md` §2 is reached through its SMTP relay.
- **Migration `1763251202_auth.js`** on `users`: password min length 8 (ACC-01), auth token duration 30 days (FEAT-14 refreshes it on each sync, so a tablet offline under 30 days stays signed in), email/password and OAuth2 identity on (OAuth2 providers empty until the hook fills them), OTP and MFA off, PocketBase's login alert left on. Templates (plain, English): verification `{APP_URL}/verify.html?token={TOKEN}`, reset `{APP_URL}/reset.html?token={TOKEN}`, subject "{APP_NAME}: …". Also tightens `children` create to `@request.auth.id != "" && @request.auth.verified = true && @request.body.owner = @request.auth.id`, so an unverified account can't hold child data.
- **Two web pages, served by PocketBase from `server/pb_public/`** (`verify.html`, `reset.html`; synced by `install.sh` like the hooks; `--publicDir` added to the unit). Each reads `token` from the query, posts to `/api/collections/users/confirm-verification` or `confirm-password-reset` (new password twice, min 8), and shows "Done. Go back to the app and sign in." or the error. No external scripts, fonts or trackers (NFR-14); inline CSS and JS; `noindex`. This avoids Android deep links (ADR-03). nginx already proxies `/` and still 404s `/_/`.
- **Verified before signed in.** Create account = `users.create` then `requestVerification`; SCR-13 says "Check your inbox and tap the link, then sign in." A password sign-in whose record has `verified = false` is not kept: the app clears the store and shows "Please verify your email first." with "Send the email again". Google accounts come back verified. PocketBase links a Google sign-in to an existing account with the same email.
- **Google sign-in through PocketBase's browser flow** (ADR-03's second option): `authWithOAuth2('google', urlCallback)` from the `pocketbase` package, the callback opening the URL with `url_launcher` in a Custom Tab (`LaunchMode.inAppBrowserView`), cancelled after 3 minutes ("Google sign-in didn't finish."). Needs a **Web application** OAuth client in Google Cloud with redirect URI `https://<SERVER_HOSTNAME>/api/oauth2-redirect`; no SHA-1, no `google_sign_in` plugin, no Play services. The Google button shows only when `listAuthMethods()` reports the google provider (otherwise hidden, so a server without the secrets still works). Add `<queries>` for https VIEW and the Custom Tabs service in the main manifest; no new permission.
- **Session store (ACC-05).** `lib/data/sync/token_store.dart`: `TokenStore` (`read()`, `write(String)`, `clear()`), `SecureTokenStore` (`flutter_secure_storage`, Android encrypted shared prefs / Keystore), `MemoryTokenStore` for tests. `PocketBaseServerClient` builds its `PocketBase` with an `AsyncAuthStore` over it. Only the token and the auth record JSON are stored; the password is passed straight to the request and never kept in a field, provider or log.
- **`ServerClient` gains auth calls** (`server_client.dart`): `authMethods()`, `signUp(email, password)`, `signIn(email, password)`, `signInWithGoogle(launch)`, `requestVerification(email)`, `requestPasswordReset(email)`, `refresh()`, `signOut()`, `deleteAccount()`, `currentAccount` (`Account(email, viaGoogle)` or null). Errors map to one `AuthError` enum: `offline` (status 0 / timeout), `wrongCredentials` (400 on auth-with-password), `emailTaken` (`validation_not_unique` on email), `weakPassword`, `notVerified`, `tooManyTries` (429), `expired` (401 on refresh), `cancelled`, `notConfigured`, `unknown`. `FakeServerClient` grows to match.
- **`AccountRepository` + `accountProvider`** (`lib/data/sync/account_repository.dart`, provider in `providers.dart`): a notifier over `ServerClient` holding `AccountState` (`signedOut`, `signedIn(Account)`, plus a busy flag and the last `AuthError`). It loads the stored session at first read (local only, no network: NFR-11). Opening SCR-13 while signed in calls `refresh()` once: `expired` → signed out with "Please sign in again."; `offline` → stays signed in. FEAT-14 watches `accountProvider` to start and stop syncing.
- **SCR-13 (`lib/features/parent/account_screen.dart`, route `/parent/account`)**, behind the parent guard (ACC-04); entry is a new "Account" row on SCR-11 (subtitle: the email, or "Not signed in"). Signed out: email and password fields, "Sign in", "Create account", "Forgot password?", "Sign in with Google" (when available), message line. Forgot password always answers "If that email has an account, a reset link is on its way." Signed in: email (and "Google" when so), "Sign out", "Delete account", and the privacy note. Without a server URL: "Accounts aren't set up in this build." and no form. Keys: `account-email`, `account-password`, `account-signin`, `account-create`, `account-forgot`, `account-google`, `account-resend`, `account-signout`, `account-delete`, `account-message`, `account-row`.
- **Sign out (ACC-06):** clears the store, nothing on the device changes. **Delete (ACC-07):** dialog "Delete the account? This removes her progress from the server. Progress on this tablet stays." → `PinPad` checked with `PinRepository` (the existing lockout applies) → `users.delete(id)`; the FEAT-12 cascade (owner → children → records) removes her server data. Offline or failure: nothing changes, message shown. Signed out afterwards.
- **Messages:** offline "Can't reach the server. Check the internet and try again."; wrong credentials "Email or password is wrong."; email taken "That email already has an account. Sign in instead."; weak "Use at least 8 characters."; too many "Too many tries. Wait a minute and try again.". Client-side checks first: email has `@` and a dot after it, password ≥ 8.
- **Privacy note (NFR-14, ADR-07)** on SCR-13, always shown: "What's stored: your email, her nickname and school year, and her practice records (answers, times, stars, badges and settings). It's kept on our own server, used only by this app, with no ads, analytics or tracking. Deleting the account removes all of it from the server; this tablet keeps its copy."
- **Plugins:** `flutter_secure_storage` and `url_launcher` (minSdk 24 is enough). Both are plugins, so the draft PR opens at T1 to prove the APK build.

## Acceptance criteria

- **AC-1** (ACC-05): `account_repository_test.dart` with `FakeServerClient` and `MemoryTokenStore`: sign-in stores a token; nothing stored or held by the repository contains the password; a new repository over the same store starts signed in without a network call; `refresh` `expired` → signed out; `offline` → still signed in. `token_store_test.dart` round-trips through `SecureTokenStore` with the plugin's mock.
- **AC-2** (ACC-01, ACC-02, ACC-03 server side): server tests against the pinned PocketBase with a local SMTP sink in the CI `server` job: sign-up → verification mail whose link is `https://<host>/verify.html?token=…` → confirm → sign in works; before confirming, the account can't create a child (400/403); reset request → mail link `…/reset.html?token=…` → confirm new password → old fails, new works; password of 7 characters refused; `GET /verify.html` and `/reset.html` return 200 HTML with no external `src`/`href`; with `GOOGLE_CLIENT_ID/SECRET` set to dummies, `auth-methods` lists google; without SMTP env the server starts and mail is off.
- **AC-3** (ACC-07): server test: deleting parent A's user removes A's children, rounds, attempts, badges and usage (superuser list finds none); B's records remain.
- **AC-4** (ACC-01..04, ACC-06, ACC-07, NFR-14): widget tests of SCR-13 with the fake client: reachable only through the PIN (direct `/parent/account` without the session lands on PIN entry); create shows the inbox text; unverified sign-in shows the verify text and Resend calls `requestVerification`; each `AuthError` shows its text; forgot shows the neutral text; Google hidden when not offered and calls `signInWithGoogle` when offered; sign out returns to the signed-out form and keeps local rounds; delete needs the right PIN (wrong PIN → no call), then signs out and keeps local rounds; privacy note visible; "not set up" build shows no form; FEAT-04 six sizes at text scale 1.3 (`layout_checks.dart`). No child screen shows anything account-related (existing tests pass unchanged).
- **AC-5** (build): CI APK build passes with both plugins; manifest permission check unchanged (INTERNET only); `flutter analyze`, `scripts/check.sh` green.
- **AC-6** (live, after Ken's setup): after "Deploy server", on the tablet with an APK built with `SERVER_URL`: create account, get the email, verify, sign in; forgot password resets it; Google sign-in works; delete removes the user (checked in the admin UI through the tunnel). Waits for the M6 test APK (Ken, 2026-11-16); noted in `verify.md` when done.
