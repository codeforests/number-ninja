# FEAT-15: Server question bank

> Implements: BNK-07..12 (D11, ADR-05) · Screens: SCR-11 ("Question bank" row) · Builds on FEAT-12 `banks` collection and FEAT-13/14 `ServerClient`
> Status: designed · Branch: `claude/project-thread-665xht` · 2026-11-17

## Scope

The generator stays the only source of questions. A "Publish bank" workflow on `main` regenerates and validates the bank, refuses a version that isn't higher than the latest published one or that drops a question id, and uploads it with its sha256 (BNK-07, BNK-10). The app, when it has a server URL, checks for a newer bank it can read at launch and on resume, at most once a day, downloads it, checks the sha256 and the same validator as the bundled bank, and keeps it in app storage (BNK-08, BNK-11). A new bank takes effect at launch or just before the next round starts, never during one; a missing or damaged file falls back to the bundled bank (BNK-09). SCR-11 shows the bank version in use and the last check, with "Check now" (BNK-12). No account is needed: `banks` is publicly readable.

Not in scope: new topics or question kinds in a published bank (they need an app update, see D4 below); deleting a published bank (Ken can do that in the admin UI); the rename (FEAT-16).

## Design decisions (this feature)

- **D1 Bank file shape.** Top level gains `"format":1` (`bankFormatSupported = 1` in `lib/domain/question.dart`); a question may carry `"retired":true` (omitted when false, so the diff stays small). `QuestionBank` gains `format`, `byId` (all questions) and keeps `byTopic` = **active questions only** (what rounds are built from). `questions` stays the full list. Code that serves questions must use active ones: `revision.dart` pool (line ~251) filters `retired`; `topic_detail_screen.dart` looks questions up through `byId` so retired ones in her history still show. Stats keep `bank.questions` (ids → topic for every question).
- **D2 Version.** `const bankVersion = 1;` in `tool/bank/bank.dart`, passed to `buildBank`; the generator writes it. To ship new questions: change templates, bump `bankVersion`, regenerate, commit through a PR, merge, run "Publish bank". The bundled asset is renamed `assets/questions/bank.json` (update `pubspec.yaml`, `generate_bank.dart`, `question_bank_loader.dart`); the bundled copy is the same file, so the next APK ships the same bank.
- **D3 Retiring.** `tool/bank/retired.dart`: `const retiredIds = <String>{...}` (empty now). The generator marks those questions `retired`; it fails if a listed id doesn't exist. Validator: per-topic minimum (BNK-03) and duplicate checks count active questions only; new `missingIds(previous, next)` returns ids of `previous` absent from `next` (BNK-10).
- **D4 Compatibility (BNK-11).** The app asks only for records with `format <= bankFormatSupported` and still rejects a bank that fails its parse or validator (unknown topic, unknown format, bad answer). Rule for later features: bump `format` (and `bankFormatSupported` in the same app release) when a bank uses anything older apps can't show (new topic, visual kind or question format). `min_app_build` is written as 0 and not read.
- **D5 Server.** Migration `server/pb_migrations/1763251204_banks.js`: `banks.version` becomes a number (drop the text field and its index, add `number` `version` required, unique index); no records exist yet. Rules unchanged (anyone reads, superuser writes). `api_rules_test.dart` cases for `banks` follow the new type.
- **D6 Publish step.** `tool/publish_bank.dart` (pure Dart, `http`): args `--server <url>` (`PB_URL` env), `--dry-run`; env `PB_SUPERUSER_EMAIL`, `PB_SUPERUSER_PASSWORD`. Steps: (1) build the bank in memory exactly as `generate_bank.dart` does and fail on any validator problem; (2) fail if it differs from the committed `assets/questions/bank.json` (the published bank is always the committed one); (3) superuser auth; (4) latest record (`sort=-version`, `perPage=1`): fail unless `bankVersion` is higher; (5) previous ids = latest published file's ids ∪ the bundled bank at the newest release tag (`git describe --tags --abbrev=0`, file `bank.json` or `bank_v1.json`), fail listing up to 20 `missingIds`; (6) upload multipart `version`, `format`, `min_app_build=0`, `sha256` (hex of the file bytes), `published_at`, `file` = `bank_v<N>.json`. Dry run stops before (6). Exit 1 with a one-line reason on every failure. Workflow `.github/workflows/publish-bank.yml`: `workflow_dispatch` (input `dry_run`, default false), runs only on `refs/heads/main`, Flutter setup as in `ci.yml`, `PB_URL=https://${{ vars.SERVER_HOSTNAME }}`, the two superuser secrets that "Deploy server" already uses. (ADR-05 named an input on `ci.yml`; a separate workflow keeps the APK build out of it.)
- **D7 App storage.** Schema v8: table `BankFiles` (`bank_files`: `version` int PK, `format`, `sha256`, `path` (file name under `getApplicationSupportDirectory()/banks/`), `downloadedAt`); `AppSettings` gains `bankCheckedAt` (nullable, last successful check) and `bankCheckNote` (nullable text: last attempt's outcome, e.g. "up to date", "downloaded version 3", "offline", "rejected: checksum"). The existing unused `AppSettings.bankVersion` is left alone. Only the newest good file is kept: after a new one is saved, older rows and files are deleted.
- **D8 `BankStore`** (`lib/data/bank_store.dart`, directory and asset bundle as parameters): `loadActive()` returns the bank with the highest version among the bundled one and each `bank_files` row whose file exists, matches its sha256 and parses with `format <= bankFormatSupported`; a row that fails is deleted with its file (BNK-09). It doesn't re-run the validator at load (done before saving). `save(info, bytes, bank)` writes `<name>.tmp`, renames, inserts the row, prunes older ones. Returns which source is active (`BankSource.bundled | downloaded`) for SCR-11.
- **D9 `BankUpdater`** (`lib/data/bank_updater.dart`, clock as parameter, NFR-08): `check({bool force = false})`. Skips (no network call) when the server URL is empty, or when `!force` and `bankCheckedAt` is under 24 h ago. Otherwise: `ServerClient.latestBank(maxFormat:)` → none or `version <= active.version` → note "up to date"; else `downloadBank` → sha256 must equal the record's → parse → `validateBank(bank, topicList: topics)` empty → `missingIds(active, new)` empty → `BankStore.save` → note "downloaded version N", set the pending flag. Any failure keeps the current bank, writes a note, and doesn't set `bankCheckedAt` (so the next launch or resume tries again). Network errors map to "offline". At most one check runs at a time.
- **D10 ServerClient.** `Future<BankInfo?> latestBank({required int maxFormat})` (GET `banks` records, `filter=format<=F`, `sort=-version`, `perPage=1`; no auth header needed) and `Future<List<int>> downloadBank(BankInfo info)` (file URL, 30 s limit). `BankInfo`: `version`, `format`, `sha256`, `fileUrl`. `FakeServerClient` gets an in-memory list of banks with bytes.
- **D11 Switching (BNK-09).** `bankProvider` stays a `FutureProvider<QuestionBank>` that reads `BankStore.loadActive()`; `bankStatusProvider` (FutureProvider) gives version, source, checked time and note for SCR-11. `bankUpdaterProvider` holds `BankUpdater`; after a download it sets `bankPendingProvider` (a `StateProvider<bool>`-like notifier). `QuizController.start` and `startRevision`, before reading the bank: if pending, clear it and `ref.invalidate(bankProvider)`. So a new bank applies at the next launch or the next round's start, never mid-round (the round's questions are already in its state, and the controller only `ref.read`s the bank). SCR-11 "Check now" invalidates `bankProvider` and `bankStatusProvider` straight away when a bank was downloaded (no round can be running in the parent area).
- **D12 Triggers.** `app.dart`: after the first frame, `bankUpdater.check()`; the existing `AppLifecycleListener.onResume` also calls it (the 24 h rule makes most calls no-ops). Neither awaits it on the UI path.
- **D13 SCR-11 row.** `ListTile` key `bank-tile`, title "Question bank", subtitle "Version N (built in | downloaded) · checked <d MMM HH:mm> · <note>" or "not checked yet"; trailing `TextButton` "Check now" (key `bank-check-now`, disabled while a check runs; hidden when the server URL is empty). Text sizes from `theme.dart`.

## Acceptance criteria

| AC | Requirement | Check |
|---|---|---|
| AC-1 | BNK-10, D1, D3 | Unit: `byTopic` excludes retired, `byId` includes them; validator ignores retired for minimums and duplicates; `missingIds` lists dropped ids; generator marks `retiredIds`, fails on an unknown retired id; regenerating gives only the `"format":1` header change in the bank diff; revision pool never serves a retired question; topic detail still shows a retired question from history. |
| AC-2 | BNK-07, BNK-10 | Server test (`server/test/bank_publish_test.dart`, in `run.sh`) against the local PocketBase: first publish uploads with the right sha256 and version; same or lower version refused; a bank missing a previous id refused; validator failure and a bank differing from the committed file refused before any upload; dry run uploads nothing; anonymous client can list and download, can't create. |
| AC-3 | BNK-08, BNK-11 | Unit (`BankUpdater` with fake client, fake clock, temp dir): newer bank downloaded, checked and saved; checksum mismatch, parse failure, validator failure, missing id and `format` too high all keep the current bank with a note; second call within 24 h makes no request, `force` does; failure leaves `bankCheckedAt` unchanged; empty server URL makes no request. |
| AC-4 | BNK-09 | Unit (`BankStore`): newest valid wins; bundled wins over an older or equal download; deleted or corrupted file falls back to the bundled bank and removes the row. Widget/controller: a download during a round leaves the round's questions unchanged; the next `start` uses the new bank. |
| AC-5 | BNK-12 | Widget: SCR-11 shows "Version 1 (built in)" and "not checked yet" on a fresh install; after a forced check that downloads version 2 it shows "Version 2 (downloaded)", the check time and the note; no "Check now" without a server URL. Layout check at text scale 1.3 (`layout_checks.dart`). |
| AC-6 | BNK-08 live | `test/live/bank_live_test.dart` (run by `server/test/run.sh`, `SYNC_LIVE_URL` as in FEAT-14): publish a version-2 copy of the bank to the local PocketBase with `tool/publish_bank.dart`, then `BankUpdater` with `PocketBaseServerClient` downloads and `BankStore` loads it. |
| AC-7 | NFR-08, all | `scripts/check.sh` green (format, analyze, tests, generator no diff); migration test v7 → v8; CI green including the APK build. |

## After merge (Ken)

1. Run "Deploy server" so the `banks` migration (D5) is live.
