# FEAT-14: Progress sync

> Implements: SYN-01..07, NFR-16 (D10, D11, ADR-04) · Screens: SCR-13 (sync section), SCR-11 (reset note) · Builds on FEAT-12 collections and FEAT-13 `accountProvider`
> Status: designed · Branch: `feat/FEAT-14-sync` · 2026-11-16

## Scope

While the parent is signed in, the app copies her rounds, attempts, badges, child profile, settings (daily limit, sound, parent-opened topics) and daily screen time to the server and pulls other devices' copies back, merging by ADR-04. It syncs at launch, on resume, after each finished round, every 5 minutes and on "Sync now", retrying with growing delays. The first sign-in on a device uploads what's already there and merges it with the account's (SYN-03). A PAR-10 reset clears the account's progress on the server and on the other devices (SYN-06). SCR-13 shows the email, last sync and any error (SYN-07).

Not in scope: the PIN and lockout (never leave the device, SYN-02); bank download (FEAT-15); more than one child per account (the first `children` record is used); deleting single records (nothing in the app deletes except reset).

## Design decisions (this feature)

- **Ids (schema v7).** `lib/domain/ids.dart` `newId(Random)` → 32 lowercase hex chars (128 random bits, `Random.secure()` in the app). The migration backfills with `lower(hex(randomblob(16)))`, the same shape. New columns: `rounds.uuid` (unique), `attempts.uuid` (unique), `app_settings.device_id` (made once; `clientDefault` for new installs). Pulled attempts point at their local round by `round_uuid` → local `rounds.id`.
- **Dirty counters, not timestamps, for push.** `rounds`, `attempts`, `badges_earned`, `daily_usage` get `dirty INTEGER NOT NULL DEFAULT 1` (backfill 1: everything unsent). Every local write sets `dirty = dirty + 1`; a push reads `(row, dirty)` and afterwards runs `UPDATE … SET dirty = 0 WHERE uuid = ? AND dirty = <read value>`, so a round finished during a push is sent again next time. Rows written by a pull are stored with `dirty = 0`. `rounds`, `badges_earned` and `daily_usage` also get `remote_id TEXT NULL` (the PocketBase record id, for updates).
- **`daily_usage` keyed by day + device.** Rebuilt in the migration with primary key `(day, device_id)`; existing rows get this device's id. `UsageRepository` writes only its own device's row; `status(day)` and `latestDay()` sum `seconds_used` and `extra_seconds_granted` over all rows of the day, so the limit holds across devices (ADR-04) and extra time granted on one tablet counts on the other. Other devices' rows come only from pulls.
- **Profile and settings fields, last change wins per field.** New table `sync_fields(field TEXT PK, changed_at DATETIME, dirty INT)` for `nickname`, `school_year`, `start_level_school`, `start_level_olympiad`, `daily_limit_min`, `sound_on`, `unlocked_topics` (the whole sorted set of parent-opened topics as one field, since the parent can also close one). `ProfileRepository.save`, `UsageRepository.setDailyLimit`/`setSoundOn` and `TopicLockRepository.open`/`close` stamp the changed fields with the injected clock (NFR-08). Backfill: profile fields from `child_profile.updated_at`, the rest at time 0, so on a second tablet the account's values win over untouched defaults. The server keeps the same map in `children.field_times` (ISO strings). Merge: for each field the later time wins; equal times keep the server's. A device whose profile is still pending (no `child_profile` row) takes the server's profile and clears `profile_pending`.
- **`sync_state` (one row):** `account_id`, `child_id` (server), `reset_epoch`, `pending_reset` bool, `cursors` (json: collection → last `updated` seen), `last_sync_at`, `last_error` (enum name). If the signed-in account id differs from `account_id`, the device treats it as a first sign-in: cursors and `child_id` cleared, every row marked dirty, so its progress merges into that account (SYN-03). Sign-out keeps the row and stops syncing.
- **Merge rules are pure functions** in `lib/domain/sync_merge.dart` (ADR-04, tested without a server): `mergeRound(local?, remote)` → insert / set finish fields (only when local `finished_at` is null and remote's isn't) / keep; `mergeBadge(localEarnedAt?, remoteEarnedAt)` → earliest wins, and a local-earlier result marks the row dirty to update the server; `mergeFields(localTimes, remoteTimes)` → per field which side wins; attempts insert when the uuid is unknown, else nothing; usage rows of other devices take the larger `seconds_used` and `extra_seconds_granted` (both only grow).
- **One sync run (`SyncService.run()`, `lib/data/sync/sync_service.dart`), serial (a request during a run sets "run again"):**
  1. `refresh()` the token (FEAT-13); `expired` → `accountProvider` signs out with "Please sign in again." and the run stops.
  2. Child: list `children` for the owner (oldest first). None → create it from local profile, settings and `field_times`. Found → if `pending_reset`, call the reset route (below), store the returned epoch, clear the flag. Else if its `reset_epoch` > local: delete local rounds (and their attempts) started before `reset_at` and badges earned before it, `forgetSession()`, store the epoch. Then merge fields both ways and update the child record if any local field won.
  3. Push dirty rows, in order rounds → attempts → badges → own `daily_usage`, in PocketBase batch requests of 100 (`pb.createBatch()`; create when `remote_id` is null, else update). A batch that fails (one duplicate makes the whole batch fail) is retried row by row: a not-unique error on create fetches the record by `uuid` (or `child + badge_id`, or `child + day + device_id`), stores its `remote_id` and, for rounds, badges and usage, sends an update; for attempts it just counts as sent.
  4. Pull each collection with `filter: child = X && updated >= cursor`, `sort: updated`, 500 per page, in order children → rounds → attempts → badges → daily_usage, merging each page in one Drift transaction, then storing the cursor (the page's last `updated`; `>=` plus idempotent merges means a same-millisecond record is never skipped). An attempt whose round isn't known yet stops that collection's cursor for this run. Own pushed records come back and merge as no-ops. Pulled rounds attach to one `play_sessions` row per run (started = the run's time).
  5. Store `last_sync_at`, clear `last_error`; if anything local changed, bump `syncProvider`'s data version (below).
- **Reset across devices (SYN-06).** New server route in `server/pb_hooks/reset.pb.js`: `POST /api/nn/children/{id}/reset`, auth required, 403 unless `owner = auth id`; in one transaction deletes the child's `attempts`, `rounds` and `badges` (screen time stays, TIM-05), sets `reset_epoch = reset_epoch + 1` and `reset_at = now`, returns `{reset_epoch, reset_at}`. New migration `1763251203_sync.js`: `children.reset_at` (date), batch API on (`maxRequests` 100, `timeout` 10 s, `maxBodySize` 8 MB). In the app, SCR-11's reset (when signed in) runs the local reset as now, sets `pending_reset`, and requests a sync; offline, the server is cleared at the next sync. The reset confirm text adds "Her other tablets clear at their next sync." when signed in. Records made after the reset on a device that was offline are kept (they start after `reset_at`).
- **Server ids on push.** Rounds, attempts, badges and usage are created with the `child` relation set to `child_id`; existing rules (FEAT-12) already restrict them to the owner's child and keep attempts create-only.
- **`ServerClient` gains record calls** (`server_client.dart`): `listChildren()`, `createChild(Map)`, `updateChild(id, Map)`, `resetChild(id)`, `pushBatch(List<PushOp>) → List<PushResult>`, `findOne(collection, filter)`, `pullPage(collection, childId, cursor, page) → PullPage(items, totalPages)`. Errors map to `SyncError`: `offline`, `expired`, `server` (5xx), `rejected` (400/403 after the row-by-row retry: logged, the row stays dirty, the run carries on), `unknown`. `FakeServerClient` keeps records in memory per collection with real `updated` times and unique checks, so two fake devices can sync through one fake server in tests.
- **`syncProvider` (`lib/data/sync/sync_controller.dart`), a notifier holding `SyncStatus(running, lastSyncAt, lastError, dataVersion)`.** Starts when `accountProvider` is signed in and a server URL is set, stops on sign-out. Triggers (SYN-05): start (launch), app resume (`AppLifecycleListener` in `app.dart`), `QuizController` after `finishRound` (`requestSync()`), a 5-minute periodic timer, and "Sync now". Failures retry after 30 s, 1, 2, 4, 8, 15 min (cap 15), reset by a success; the periodic timer and lifecycle triggers still run. Timers come from an injected `SyncTimers` (clock + timer factory) so tests drive them (NFR-08). A run never blocks UI: it is async, merges in transactions of at most 500 rows, and screens keep reading Drift (SYN-01). When `dataVersion` changes, the controller invalidates `childProfileProvider`, `topicProgressProvider`, `topicLocksProvider`, `statsDataProvider` and reloads the screen-time status; a round in progress keeps its own state.
- **SCR-13 sync section (SYN-07), signed in:** "Last synced: today, 2:31 pm" (or "Not synced yet"), "Syncing…" while running, error line, "Sync now" button. Keys: `account-last-sync`, `account-sync-error`, `account-sync-now`. Messages: offline "Not synced: no internet. It will try again."; server "The server had a problem. It will try again."; rejected "Some records weren't accepted by the server."; expired → the FEAT-13 signed-out message "Please sign in again.".
- **No new plugins.** Batch and filters come from the `pocketbase` package (0.26.0, `createBatch`).

## Acceptance criteria

- **AC-1** (schema): `migration_test.dart` v6 → v7: every round and attempt gets a distinct 32-hex uuid, attempts still point at their rounds, `daily_usage` rows keep their values under this device's id, all rows dirty, `sync_fields` backfilled (profile fields at `updated_at`, the rest at 0); a fresh v7 install has a device id.
- **AC-2** (ADR-04, SYN-04): `test/domain/sync_merge_test.dart`: a round's finish only moves from empty to set (a remote unfinished copy never clears a local finish); badge earliest date wins both ways; per-field later time wins, ties keep the server's; attempts by uuid never doubled; usage max per device row; day total = sum over devices.
- **AC-3** (SYN-02, SYN-03, SYN-04, SYN-06): `test/data/sync_service_test.dart`, two devices (two in-memory Drift databases) through one `FakeServerClient`: A's rounds, attempts, badges, profile, limit, sound, opened topics and usage appear on B; B already holding progress before its first sign-in ends with the union and nothing doubled (counts checked); a round finished on A after a push arrives finished on B; a later limit change on B wins on A; screen time used on A and B adds up in `status(day)` on both; the PIN and lockout never appear in any pushed body; A's reset (online and offline-then-online) clears the server and B's older records at B's next sync while B's newer rounds stay; a different account on the same device merges into that account; a failed batch with one duplicate falls back row by row and sends the rest; a round finished during a push is sent next run.
- **AC-4** (SYN-05, SYN-01): `sync_controller_test.dart` with fake timers: runs at start, on resume, after a finished round, every 5 minutes, on Sync now; failures back off 30 s, 1, 2, 4 min and reset after a success; no runs while signed out or without a server URL; `expired` signs out. A quiz round played while a sync is pending finishes with no wait (QuizHarness, fake client with a delayed response).
- **AC-5** (SYN-07, SYN-06 UI): SCR-13 widget tests show the last sync, "Syncing…", each error text, and Sync now calls the controller; reset confirm shows the other-tablets line only when signed in; six sizes at text scale 1.3 (`layout_checks.dart`).
- **AC-6** (server): server tests in `server/test/test/sync_test.dart`: the reset route clears A's child rounds, attempts and badges, keeps daily usage, bumps the epoch and sets `reset_at`; B can't reset A's child (403); unauthenticated 401; batch create of 100 records works and a duplicate uuid fails the batch.
- **AC-7** (NFR-16, live): `test/live/sync_live_test.dart` (skipped unless `SYNC_LIVE_URL` is set; run in the CI `server` job against the pinned local PocketBase): a first sync of 20,000 attempts in about 1,000 rounds finishes under 60 s; a second sync with one new round sends 1 round + 10 attempts (counted by the client) and pulls only those; a second device pulls it all.
- **AC-8** (build): `scripts/check.sh` and CI green; `flutter analyze` clean; manifest permission check unchanged.
- **AC-9** (live, M6 APK): on Ken's tablet and a second device with the M6 APK: progress made on one shows on the other after Sync now; reset on one clears the other. Noted in `verify.md` when Ken has tried it.
